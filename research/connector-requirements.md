# Yêu cầu connector ChatGPT / Claude đối với MCP server xT

Ngày xem nguồn: 2026-10-15. Chỉ dùng tài liệu chính thức (OpenAI, Anthropic, modelcontextprotocol.io, keycloak.org). Mục nào không đọc được trang chính thức ghi "chưa xác nhận".
Ngữ cảnh: `research/spike-mcp-auth.md`, `research/spike-mcp-apps.md`.

## 2. Spec MCP: bản mới nhất (tóm tắt auth)

Bản "current" ở modelcontextprotocol.io/specification/versioning là **2026-07-28** (đã thay 2025-11-25). Claude Docs chỉ nói Claude theo các bản 2025-03-26, 2025-06-18, 2025-11-25 [A3]. Hai bản này khác nhau ở chi tiết handshake: bản 2026-07-28 bỏ `initialize` kiểu cũ, mỗi request khai `protocolVersion` trong `_meta`, có `server/discover` [S2]. Với xT: dùng SDK `mcp` 2.x, hỗ trợ cả hai nếu SDK cho phép (chưa kiểm khả năng tương thích ngược của SDK; chưa xác nhận).

| Mục | Nội dung chính thức (bản 2026-07-28) [S1][S3] |
|---|---|
| PRM RFC 9728 | "MCP servers MUST implement OAuth 2.0 Protected Resource Metadata"; client MUST dùng PRM để khám phá AS |
| Discovery của AS | MUST có ít nhất một: RFC 8414 hoặc OIDC Discovery |
| CIMD vs DCR | Thứ tự client SHOULD: (1) pre-registered, (2) CIMD nếu AS có `client_id_metadata_document_supported`, (3) DCR fallback, (4) hỏi người dùng. "Dynamic Client Registration is deprecated. New implementations should use Client ID Metadata Documents instead." AS và client SHOULD hỗ trợ CIMD, DCR là MAY |
| Resource indicators RFC 8707 | Client MUST gửi `resource` ở cả authorize và token request, dùng URI chuẩn của MCP server, "regardless of whether authorization servers support it". Server MUST xác thực token được cấp cho mình (audience); MUST NOT nhận token khác |
| `iss` RFC 9207 | AS SHOULD trả `iss`; client MUST kiểm theo bảng; dự kiến nâng lên MUST ở bản sau |
| PKCE | Bắt buộc, AS phải quảng bá `S256` (spec 2025-11-25, qua tài liệu Claude [A4]) |
| Scope | Server SHOULD đặt `scope` trong `WWW-Authenticate`; client ưu tiên `scope` của 401, rồi `scopes_supported` |
| Step-up | Thiếu quyền lúc chạy: HTTP 403 + `WWW-Authenticate: Bearer error="insufficient_scope", scope="...", resource_metadata="..."`; nên đưa đủ scope cần cho thao tác trong một challenge; client lấy hợp (union) scope cũ + mới rồi xin lại token, thử lại có giới hạn; server phải tính phân cấp scope |
| Token | Header `Authorization: Bearer` trên MỌI request; không đặt token trong query; token hết hạn/sai: 401 |
| Refresh | Client MAY thêm `offline_access` nếu có trong `scopes_supported`; server KHÔNG nên đưa `offline_access` vào `WWW-Authenticate` hoặc PRM `scopes_supported` |

## 3. Keycloak (hướng dẫn MCP chính thức) [K1][K2]

| Mục | Kết quả |
|---|---|
| Phiên bản tối thiểu | Trang `securing-apps/mcp-authz-server` không nêu số phiên bản tối thiểu (chỉ thấy bộ chọn tài liệu "Nightly 26.8.1"): chưa xác nhận. Thông báo 26.6.0 (2026-04): thêm hỗ trợ thử nghiệm CIMD và "Keycloak can now act as an authorization server for MCP 2025-11-25 or later" (qua kết quả tìm kiếm; chưa đọc trọn trang). Docstring `fastmcp` nói Keycloak >= 26.6 (spike). Dùng 26.8.1 như spike |
| Bản MCP spec | 2025-03-26: Supported. 2025-06-18, 2025-11-25, 2026-07-28: **Experimental** |
| DCR | RFC 7591: Supported |
| CIMD | Experimental, cần `--features=cimd` + client profile executor `client-id-metadata-document` + client policy `client-id-uri`. **ChatGPT: không hỗ trợ** ("Keycloak rejects its CIMD format") |
| Resource / audience | Cách 1 (không cần RFC 8707): scope tùy chọn + `Audience` mapper với "Included Custom Audience" = URL MCP (đúng cách spike). Cách 2: `--features=resource-indicators` (Experimental): kiểm `resource` với thuộc tính `resource_url` của client, sai thì `invalid_target`; `aud` chỉ gồm giá trị `resource` |
| Anonymous DCR | Cấu hình policy (allowed scopes, web origins, trusted hosts) cho MCP Inspector/clients DCR |

Hệ quả cho xT: ChatGPT và Claude đều chạy được với Keycloak qua DCR (stable, đã có spike). CIMD: ChatGPT thất bại với Keycloak (ghi rõ trong docs Keycloak), Claude chỉ chọn CIMD khi AS liệt kê `none` trong `token_endpoint_auth_methods_supported` (spike: Keycloak không liệt kê), nên không cần bật `cimd`. Không bật feature flag thử nghiệm trừ khi cần.

## 4. Việc xT phải làm (checklist)

1. MCP server: Streamable HTTP tại `/mcp`, 401 kèm `WWW-Authenticate: Bearer resource_metadata=..., scope=...`, PRM tại `/.well-known/oauth-protected-resource/mcp`, `resource` khớp chính xác URL connector.
2. Keycloak: DCR ẩn danh với Trusted Hosts (`chatgpt.com`, `claude.ai`); audience mapper ở realm default scope; refresh token rotation; `openid email` + scope nghiệp vụ; S256; `authorization_response_iss_parameter_supported: true`.
3. Redirect: `https://chatgpt.com/connector_platform_oauth_redirect`, `https://chatgpt.com/connector/oauth/*` (dự phòng), `https://claude.ai/api/mcp/auth_callback`, loopback cho Claude Code.
4. Mạng: Keycloak và MCP truy cập công khai HTTPS, cho phép `160.79.104.0/21`; endpoint OAuth phản hồi dưới 10 giây.
5. Tool: `title`, `readOnlyHint`, `destructiveHint`, `openWorldHint` đầy đủ; tách đọc/ghi; kiểm quyền server-side.
6. MCP Apps: chuẩn `text/html;profile=mcp-app` + `_meta.ui.resourceUri`; tool app-only `visibility:["app"]`; kết quả nhỏ; test thật trên ChatGPT (Business/Enterprise) và Claude Desktop.
7. Chưa xác nhận, cần test thật: gói Plus của ChatGPT; ChatGPT có hiện confirm cho tool `readOnlyHint:false` trong custom connector (hành vi cụ thể); Claude gửi `resource` hay không; UI `tools/call` thực tế trên ChatGPT; SDK `mcp` 2.3.0 với bản spec 2026-07-28.
